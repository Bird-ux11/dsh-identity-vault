# 身份记忆库 · dsh-identity-vault

统一 DSH 记忆插件，提供唯一身份、主人绑定、独立 memory 索引、原生 MCP/Skill 接口、多轮事件总结、记忆维护、跨事件长期印象，以及事件纠错、撤回、人物资料修订和审计。`dsh-fish-memory` 与 `billion-context` 由主插件管理，按实际接口能力判断兼容性，不锁定发行版本；重要长期事实写入 MCP，全部事件 Skill 按实际来源时间保留 240 小时。升级沿用一个 bundle。

## 每轮流程

1. 从可信传输来源识别当前人物，由 memory 定位其 MCP。先实际读取 self 和当前对象的 MCP：已确认资料、长期推测印象、重要事件引用，以及近期 Skill 索引。
2. 只在这些人物引用的事件中按本轮主题、关键词和近期时间选择，再通过 DSH 正式 MCP/Skill 服务读取正文。多人事件共用一份正文；读到授权事件后可读取其中其他参与者的 MCP，但不沿新人物无限展开其其他事件。仅命中标题不能声称已读过正文。
3. 完成的连续多轮先暂存来源引用；明确结束当前话题，或空闲满 10 分钟后，在后台用 DSH 已配置的模型整理这段对话。受管“鱼的记忆”先提供提炼候选，主插件结合原始公开发言进行二层分类。同群多人讨论同一主题共用一个事件，每人的表达绑定真实来源，self 的公开回复单独记录。
4. 每个事件分别记录“发生了什么、讨论框架、结果、当时的评价、未解决事项”。事件附来源时间；主观评价附评价者、评价对象和消息依据，不能直接变成永久人格。
5. 正文先写入 `SKILL.md`，再维护长期状态、相同事件关联、索引和人物来源引用。有本人明确证据的长期事实另外投影为 MCP 重要记录。全部 Skill 的检索分数在 0 至 10 天内逐渐降低，满 240 小时停止召回；重要度、状态替代和重新总结均不延长 Skill 寿命。
6. 明确的新状态替代 MCP 的当前值，重要历史记录保留实际时间和来源，并标明仍有效、已替代或已清除。每天北京时间 00:00 清理到期 Skill 正文，启动时先补做重要投影与维护，再补做清理；MCP 核心身份和重要投影不随十天周期遗忘。
7. 事件归档后在后台按人物汇集独立证据。至少 3 个独立事件、跨 2 个北京时间自然日支持同一模式时，才把简短的长期推测印象写入人物 MCP。下一次遇到该人物先加载这些印象，不必重新读取所有旧事件。

同一 QQ 跨群共用身份与群聊记忆，事件保留来源群、时间和作者。私聊、本机主人对话不会自动进入群聊上下文。读到事件后，只能扩充该授权事件真实涉及的人物权限；昵称、正文中的 QQ 号、转发内容和“我是主人”的声称不能授权身份。

目前使用主题与关键词匹配，并加入当前人物的近期事件，没有语义 embedding。每次最多选择 6 条主题，近期补充最多 2 条，总注入预算不超过 18000 字符，省略时标记。旧摘要回退也包含在预算中。

上下文中的缩略有 `truncated` / `profileIsSummary` 标记，并保留完整 MCP 资源 URI；存储正文不因注入预算而截断。单个 Skill 文件损坏时会警告并跳过该事件，核心身份仍可读取。

“先这样”“再见”“结束这个话题”等直接收尾表达触发归档；明确换话题时先结束之前的对话段。普通连续回复不会每轮拆成一个事件。暂存内容仅为会话、参与者与消息来源引用，不额外保存聊天原文；重启后按原活动时间恢复，已空闲满 10 分钟的对话会补做归档。每个主题的时间取实际参与该主题的最后一轮来源时间，不用后台总结生成时间延长记忆寿命。

下一轮最多等待已关闭对话的前序摘要 60 秒，超时继续聊天并标明待处理。主题后台任务总超时为 15 分钟，有租约、重启恢复和最多 3 次尝试。“鱼的记忆”提炼与主插件总结分别需要后台模型调用，长输入分段后再合并，因此不保证每个话题只调用一次模型。超过 300 条消息、80000 字符或主题摘要预算时失败，不保存截断的半份记忆；取消、缺失来源、模型失败或格式错误也不伪造摘要。

## 事件内容与长期核心

| 层级 | 保存内容 | 更新与遗忘 |
|---|---|---|
| MCP 核心人物形象 | 已确认的身份、说话风格、人物风格、职业和长期状态，以及 self 的稳定身份 | 不随十天周期遗忘；`currentState` 保存当前长期状态，新状态取代旧状态 |
| MCP 重要事件投影 | 经证据校验的长期事实、归属、实际时间及来源 ID | 不自动过期；保留更新历史，旧状态不能冒充当前状态；不复制整份聊天摘要和当时评价 |
| MCP 长期推测印象 | 跨事件重复出现的说话与互动方式，附证据 ID、时间和推测标记 | 满足 3 事件、跨 2 日门槛后保存；不按十天遗忘，新证据可更新；与已确认身份分开 |
| MCP 近期 Skill 索引 | 该人物参与的有效事件位置和主题等元数据 | 从同一份 memory 索引派生；Skill 到期、归档或遗忘后不可召回 |
| 事件 Skill | 具体发生的事、讨论过程框架、各方表达、结果、当时评价、遗留问题 | 全部按原始来源时间满 240 小时淡忘，包括曾产生重要 MCP 投影的事件 |
| memory 索引 | 七项轻量元数据和内容位置 | 新事件发布时更新；遗忘后保留终态以防重复恢复 |

事件中的“事实”指可归属于聊天来源的陈述和发生的互动，并不意味着已在现实世界独立核实。评价只代表相应人物在当时的看法；无法确定评价者、对象或来源时不能编造。事实与主观评价分开存放，稳定人格不会被单次情绪、一次争执或临时状态自动覆盖。只总结实际聊天内容，不总结思考过程、工具日志或桥接提示。

## 人物链路与跨事件印象

```text
memory 七字段统一索引
  → 当前人物的 MCP
      ├─ 已确认 profile / currentState
      ├─ longTermImpressions：跨事件推测印象
      ├─ importantEventReferences → 重要 MCP 事件
      └─ recentSkillIndex → 对应事件 Skill 正文
```

人物 MCP 是调度的中间节点，不复制每份事件正文。所有事件仍在同一份轻量索引中；多人共同讨论的事件可被多个人物引用，但正文只存一份。最近事件的索引与实际正文读取分开，索引出现不代表内容已加载。同一 QQ 跨群归于同一人物，公开群聊证据可以共同支持印象；私聊与本机主人证据保持各自的可见范围。

长期印象只概括该人物本人反复表现的表达和互动方式。别人的评价、单次情绪、同一事件的重复摘要、同一批后端候选都不能充当多个独立证据；旧印象本身也不能反复作为证据强化自己。self 可以根据自己的公开回复形成行为观察，但不因此改写主人确认的核心人格。职业、长期状态等明确事实仍走既有的重要 MCP 投影流程。

提炼使用 DSH 已配置的模型，在后台运行，不让每次回复都等待提炼。结果与已确认身份分开，明确标为 `inferred`，保存支持事件 ID 和实际时间。Skill 到期后删除事件正文与近期引用，已经达标的概括性印象继续保留；这不是普通事件摘要的永久备份。尚未达到门槛的普通经历仍遵守十天期限，过期后不会重新生成正文来凑证据。

后台保存输入指纹和处理状态，避免对同一批证据反复调用模型；已经校验的概括先暂存，MCP 写入失败时重试同一结果。暂存只含概括和来源元数据，不复制普通事件正文；重启后也可继续提交。清理先完成这类待写概括，再删除 Skill 和引用。写入持续失败时，已到期 Skill 仍立即停止召回，物理删除等待重试成功，避免丢掉尚未保存的概括。

没有足够证据时不生成印象，模型也可以判断没有一致模式并返回空结果。提炼是有证据约束的模型推测，不等于客观人格结论；主人可显式撤回不准确的印象。每条印象最多保留 1000 个支持事件、每人最多 128 条分范围印象，达到上限会报告 `IMPRESSION_CAPACITY_EXCEEDED` 并保留原记录，后续证据压缩策略待扩展。

## 记忆修订与纠错

在本机 DSH 主人对话中直接表达纠错要求即可，例如“这段讨论的结果记错了，实际是……”“我已经换工作，把职业改成……”“撤回你认为我总是……的印象”。模型先读取准确记录和版本，再调用修订工具。涉及多人或多个事件、无法确定目标时先澄清。插件本身不依赖固定口令，也不把旧摘要中的纠错指令当作主人授权。

| 对象 | 修订行为 | 关联处理 |
|---|---|---|
| 仍有效的事件 Skill | 更正完整结构化摘要，或撤回整件事件 | 保持原事件 ID、实际发生时间、作者与来源；索引和会话缓存更新 |
| MCP 中的错误重要投影 | 撤回来源事件；原 Skill 已淡忘也可操作 | 从正常 MCP 召回移除，重要索引归档；不会误把旧事实视为现状 |
| 已确认人物资料 | 明确改值或用 null 清除错误字段 | 旧自动状态退出当前值，旧任务不能覆盖这次修订；身份主键及主人绑定不变 |
| 推测长期印象 | 按人物、可见范围及印象 key 撤回 | 阻止旧支持事件和同源重复证据再次生成被否定印象；新的证据仍需至少 3 个独立事件、跨 2 个北京时间自然日 |

正常变化与纠错区分处理：“以前在甲公司，现在在乙公司”可以保留过去事实；“从没在甲公司工作，是记错了”应撤回错误投影并明确更新资料。资料修改不静默改写所有旧事件，事件纠错也不会把修正摘要伪装成当事人新发言。修订后的事件仍可作为短期回忆，但不自动重新升为长期事实或印象证据；新的本人发言或明确的资料纠错负责确认长期状态。

撤回或更正事件时，先持久保存失效标记，再修改 Skill。依赖该事件或同源重复证据的长期推测印象会撤下，相关自动当前状态失效。已有手动资料保留内部原值，但不能悄悄作为旧状态回退显示；明确资料修订可重新确认或清空该字段。未受影响的新状态保留。已经在推理中、待写入或重启恢复的旧决策都会重新检查证据有效性。

事件修订采用内容哈希检查，防止对过时版本覆盖写入；每次操作有唯一修订 ID，相同 ID 的重试幂等，不会重复改写。中途失败的事件修订保存在 `revisions/event-queue.json`，约 5 秒后重试，启动时先恢复。存在未完成事件修订时，MCP/Skill 召回暂时停止，避免读取半完成状态；工具返回 `pending` 时不能声称纠错已经完成。身份与印象修订在单一身份事务内提交，失败可用同一修订 ID 重试。

排队的替换摘要仍受原事件的 240 小时期限约束，到期先清除待写正文；之后只完成撤回与来源失效，不重建已淡忘的 Skill。失效标记写入持续失败时，清理会保留来源元数据等待重试，但已过期内容不可召回。成功回执和审计只留动作、目标、时间、版本、哈希等元数据，不保留旧的普通聊天摘要作为永久历史。可查看审计，但不会自动回滚已撤销的错误结论。

所有直接修订工具要求可信主人身份。本机主人可管理全部记录；QQ 主人仅能操作当前授权范围内的记录，群内不能查看或修订私密记录，完整审计只在本机提供。群友自己的新事实仍经真实来源、主题总结与长期状态维护更新。主人 QQ 未绑定时，在本机 DSH 对话中即可纠错，群内不能凭“我是主人”认领权限。

已进入当前会话上下文、原 DSH 日志或当前压缩工作区的旧文字不会被本插件追溯擦除。新读取以修订后的库为准，系统规则要求放弃已撤销结论；由旧来源回放的长期写入会被屏障拒绝。实际模型是否正确理解含糊纠错表达，仍需真实对话检验。

## 记忆可信度 β

每轮注入的记忆都带 `trust` 字段：`beta`（-10 到 10 的整数）、`band` 和 `why`。β 借鉴 dsh-rofm 的分级用法，但这里不是概率，而是证据链强度：谁说的、是不是本人说的、有没有被主人更正过、状态是否仍然有效。它决定一条记忆能不能直接被引用，而不是被引用的可能性。

| 分级 | 范围 | 使用规则 |
|---|---|---|
| 可靠 | β ≥ 7 | 可直接当作已确认记忆引用 |
| 需核实 | 0 ≤ β < 7 | 引用前先用本轮对话、MCP 记录或 `memory_inspect_record` 核实，不得当作已确认事实 |
| 仅线索 | β < 0 | 只能提示方向，不能据此断言，也不能写入长期状态 |

分数在读取时按持久化证据推导，不调用模型、不写进不可变正文，也不改变事件哈希：

| 记录 | β | why |
|---|---|---|
| 主人更正过的事件摘要（`replace` 修订） | 8 | `owner-corrected` |
| 本机主人对话的事件摘要 | 5 | `owner-dialogue` |
| 群聊中当事人直接发言的事件摘要 | 4 | `direct-quote` |
| 只有 self 自述来源的事件摘要 | 1 | `self-claim` |
| 没有可用来源的摘要 | 2 | `summary-only` |
| MCP 重要记录 `current` / `cleared` / `superseded` / `revoked` | 8 / 6 / 3 / -10 | `current-state` 等 |
| `currentState`：主人陈述的 owner/self 资料 | 9 | `owner-stated` |
| `currentState`：主人转述他人 | 4 | `owner-stated` |
| `currentState`：本人自述（宿主已校验） | 5 | `person-stated` |
| 长期推测印象 | -2 | `inference` |
| 画像观察 / 提取事实 / 主观评价 | 5 / 4 / 2 | `verbatim` 等 |

β 出现在四处：注入块里每条身份记录、事件和重要记录的 `trust`；`identity_read` 返回的 currentState、长期印象与画像；事件 Skill 正文首行的提示（`> 记忆可信度 β=+8（可靠）：…`）；维护器状态里的改写计数。事件 Skill 的首行只在读取时拼接，磁盘上的不可变正文和哈希保持不变。

主人可用 `memory_rate` 改写某条事件的 β，写入 `<身份目录>/trust-overrides.json`，不修改事件正文；`reset: true` 删除改写、恢复自动推导。改写会把整条记录的 `why` 变成 `owner-rated`，读取时优先于自动分数。

## 重要投影与记忆维护

“重要”在这里指会持续的职业、工作或生活状态，以及本人明确确认的长期说话风格、人物风格。事件摘要新增 `stateChanges` 候选，只允许 `occupation`、`longTermStatus`、`speakingStyle`、`characterStyle` 四种字段，以及 `set`（当前状态）或 `clear`（明确结束旧状态）。普通聊天输出空数组；`importance` 只影响初始检索排序，分数再高也不会自动获得永久保留。

长期候选必须有当事人自己的实际发言依据。临时情绪、一天的状态、未来计划、假设、转述他人和主观评价不进入长期状态；不能从语气自行推测人格。DSH 的 self 长期资料只能由可信主人明确确认，DSH 自己的回复和其他群友无权自动改写。身份、角色权限与 QQ 绑定不属于自动维护字段。

维护器按可信证据时间更新 MCP 的 `currentState`，相同人物、相同字段的新状态替代旧状态；过时任务重试不会倒退到旧资料。群聊状态可跨群读取，私聊和本机主人状态保持原可见范围。`currentState` 在解释当前状况时优先于同字段旧 `profile`，`clear` 表示旧值已结束；手动 `profile` 原值独立保留，不在后台直接覆盖。主人通过 `identity_update_profile` 明确修订对应字段时，旧自动状态退出当前值，旧事件重放不能撤销这次修订；之后实际发生的更新仍可继续维护。

重要事实和其证据元数据保存为独立 MCP 投影，原始 Skill 仍在来源时间满 240 小时时到期。被新状态替代或明确结束的旧 MCP 记录作为历史保留；读取时以 `currentState` 和记录状态区分过去与现在。`clear` 不会让旧工作或旧状态重新变成当前事实。重要度不延长 Skill 寿命，也不能单独将内容提升为 MCP 重要记录。

重复事件采用保守的逻辑归并：比较同一可见范围、同一实际参与者下的完整归属摘要、事实、评价及长期状态内容，做空白、字形与大小写规范化后完全一致才关联。仅标题相似、关键词相同或语义接近不自动合并。召回时只读取一个代表事件，并附各次发生时间、参与者和来源 ID；每次真实经历及不可变正文仍保留，不冒充只发生过一次，也不因归并删除正文。用户主动归档的状态不会因解除归并而自动恢复。

维护在事件提交后、启动时及运行中定期执行。维护器重用已保存的结构化摘要，本身不额外调用模型；后端提炼和二层分类的模型预算单独计算。写入失败保留可重放来源，以幂等事务重试，重启后补做；运行中从约 1 秒开始退避，最长约 60 秒后再试。重要投影、状态、归并和索引维护未成功时，清理先等待维护完成，避免先删掉尚未保存的重要来源。运行状态只记录计数、待重试标志和紧凑错误码，不写聊天正文或完整错误堆栈。

## 两个受管后端与统一入口

`dsh-fish-memory` 的提炼模块运行在主插件创建的隐藏 Node 子进程内，由宿主提供现有 DSH 模型调用；不再独立挂载它的原生档案库、召回或工具。提炼按人物和日期分批，每批最多 8000 字符、总计最多 64 批，主体数最多 9 个。它给出的分类与文本只是候选，不能自行写入核心身份。

受管鱼记忆在可信对话的主题结束或空闲满十分钟后处理任务，不扫描工作区。诊断以统一插件 `runtime-status.json` 中的 `managed.fish` 为准：`mode: topic-candidates`、`workspaceScan: false`、`activity: awaiting-topic` 表示正在等待主题，`extracting` 表示正在提炼；同时提供调用计数与最近开始、完成时间。以前独立插件留下的扫描日志不代表受管子进程的当前状态。

`billion-context` 的原生 DSH 桥通过 `ctx.plugin` 作为主插件子组件挂载，原始压缩代理运行在主插件拥有的独立 Node 子进程中。启动探测代理接口、原生桥工具、受管重启能力、监听端口、代理 PID 与父进程 watchdog；使用专属配置和工作目录，禁止代理自动更新及祖先会话继承。子进程异常可重启，卸载时只停止自己拥有的进程。版本仅用于诊断和核对运行进程是否属于已安装包，不与某个发行版本白名单比较；不自动下载上游更新或附着来路不明的代理。

本插件自身实现压缩门控，不依赖上游门控文件。启动时等待托管结果，最长 60 秒：受管桥就绪后才让 preset 关闭原生基础压缩；失败或超时则放行 preset 使用原生基础压缩，晚到的受管桥不能再抢占同一启动周期。托管初始化失败会释放其后端，本进程不自动重新选择压缩实现，修复后需要重启 DSH。门控只协调压缩，仍保留原 preset、工具结果裁剪与重试策略。升级和改变此模式应完整重启 DSH。

### 能力兼容

| 组件 | 接入时实际检查 |
|---|---|
| QQ 桥 | 接收与发送流程、真实数字 QQ 和群号、分人消息批次、用户原话范围、公开回复选择规则，以及可校验和恢复的适配补丁 |
| 鱼的记忆 | 提示词构建与条目解析导出、返回格式和独立 IPC；用合成数据在真实子进程中握手，不调用模型或读取人物资料 |
| billion-context | 可定位的原生桥和代理入口、桥工具注册、代理状态与检索接口、由主插件控制的代理启动和恢复，以及进程归属 |

三个适配器均不按固定版本号或预先写死的上游源码哈希决定兼容。鱼的记忆支持原模块位置及包明确导出的 JS 子模块；billion-context 支持包声明的入口及已知布局；QQ 适配器按已有收发契约进行结构校验。文件动态指纹仍用于启动一致性、补丁完整性和原件恢复，不能移除这些校验来强行接入不兼容接口。

版本更新但接口契约保持兼容时可继续使用；缺少必要能力时会报告具体错误。任意 API 重命名、全新数据格式或 QQ 收发逻辑重写仍可能需要扩展适配器，并不承诺所有未来版本自动可用。已验证的本机上游基线为 QQ 桥 1.0.7、鱼的记忆 1.3.3、billion-context 0.1.208；这些是验证记录，不是版本限制。

“鱼的记忆”的提炼结果，以及能够精确对应当前宿主会话与公开消息的压缩结果，都进入 `backend-candidates.json` 临时收件箱。候选带实际作者、消息 ID、来源范围和原始时间，主插件对照已验证的公开聊天进行第二次分类；候选文字和后端标签不构成事实证据。单批最多 64 条、总候选文本最多 32000 字符，收件箱上限 8 MiB。收件箱与 memory 的七字段索引分离，不把候选直接注入人格。

压缩结果到达较晚时，等待原主题任务完成，再独立进行二层分类；只发布经校验的重要 MCP 投影。普通内容已由原主题任务生成 Skill，不因迟到压缩重复生成另一份 Skill。已保存的二层重要决策在写入成功前保持可重试；超过十天时只保留这份重要决策和证据元数据，候选文本仍删除。其他过期候选按来源时间清理，未分类就过期的批次单独计数。没有精确消息对应、角色不明、重复文本存在歧义、跨群范围混杂或含工具/思考来源的压缩块会隔离，不猜作者、不直接升为长期记忆。QQ 包装导致原始文本不相等时也宁可跳过，所以不能承诺每个压缩块都能纳管。

历史记忆统一从 `memory_recall` 读取，billion 的 `search_context` 转接这一入口；`acp_rule` 持久规则写入关闭。工作上下文的压缩、解压和检索只能针对已经验证的当前会话和现存块/消息引用，不能恢复祖先或其他会话。普通事件的十天遗忘指本插件的 Skill 与对应摘要引用；billion 当前压缩工作区、原 DSH 聊天日志和已安装后端的历史数据不在本轮全局清理范围，不能将本版描述为磁盘上所有聊天数据十天彻底擦除。

## 索引、正文与 MCP

memory 索引存于单独目录，条目顶层严格只有七个字段：

| 字段 | 内容 |
|---|---|
| `id` | 稳定索引 ID |
| `topic` | 短主题 |
| `time` | 事件时间 |
| `importance` | 0 到 1 的检索权重 |
| `triggers` | 触发关键词 |
| `status` | `active`、`archived` 或 `forgotten` |
| `location` | Skill 路径或 MCP 地址，以及可信可见范围 |

索引不存摘要正文或人格资料。事件正文位于身份目录下的 `topics/events/<事件ID>/SKILL.md`，记录各方表达、self 回复、五类事件信息、受限长期状态候选和来源 ID。归并、到期和处理元数据在主题 manifest 中，索引仍只有七字段。人物档案追加主题位置与来源引用，到期时清理对应 Skill 引用；MCP 重要投影及其引用独立保留。新流程不永久复制完整聊天原文。

核心身份通过 DSH 原生 `mcpResources` 服务提供，服务器名 `identity-vault`：

```text
identity-vault://identity/self
identity-vault://identity/owner
identity-vault://identity/qq/<数字QQ号>
identity-vault://event/<重要事件ID>
```

可通过 DSH 的 `list_mcp_resources`、`list_mcp_resource_templates`、`read_mcp_resource` 读取。返回当前授权的核心资料、重要投影、来源引用和有证据的人物观察；重要投影只包含已确认长期事实及更新历史，不是完整事件 Skill 的永久备份。读取 self 也不能枚举其他人物的私有记录。Skill 使用正式 provider 和 `skill` 接口，目录与正文按代理、会话代次及授权人物过滤。本版提供 DSH 内原生资源适配器；独立对外的 stdio/HTTP MCP 服务不在范围内。

来源引用留存不代表 Skill 仍 active。归档、遗忘或已到期的任何 Skill 不参加正常检索；MCP 重要投影使用独立资源与索引。清理先原子发布无正文、无人名和消息证据的事件墓碑，再将 Skill 索引设为 `forgotten`、清理人物 Skill 引用，最后删除该事件的固定 `SKILL.md`。删除失败保留紧凑错误码并重试；重启、旧任务回放和旧摘要迁移都不能让已遗忘 Skill 复活。

每天北京时间 00:00 执行清理，运行中失败一分钟后重试，重新启动时补漏。十天按实际经过的 240 小时计算，不按跨过了几个自然日计算。保留最小事件 ID、时间与清理状态用于去重；到期任务不再调用模型重建正文。只删除本插件管理的事件文件和相应摘要引用，DSH 自己的聊天日志仍由 DSH 管理。

MCP 核心身份和重要事件索引不跟随 Skill 到期变为 `forgotten`；明确撤回的重要事件投影可以归档，self/owner 核心身份始终受保护。

## 唯一身份与主人绑定

- `self` 是 DSH 自身唯一身份，`owner` 是主人独立身份；初始资料留空，不猜姓名、人格或 QQ。
- 未绑定 QQ 也能保存本机主人对话。之后在有主人权限的本机 DSH 对话明确要求“把我的 QQ 号……绑定为主人身份”，由 `identity_bind_owner` 完成。
- DSH 官方的 `user-approval` 权限设置控制消息不授予身份权限，也不作为聊天内容归档；0.9.2 修复了它与本机用户消息同轮出现时误触发来源拦截的问题。其他未知来源、混合聊天来源和子任务仍按原规则限制。
- 普通人物按数字 QQ 号全局去重。首次被插件观察到的群为归档位置，后续群只存引用。先在私聊出现时暂存于 `direct/QQ`，首次进群再迁移，旧地址保留重定向。
- 群昵称属于成员关系。同昵称不合并，同一 QQ 改昵称不分裂。
- 主人后绑定会合并已有档案、事件、主题引用和任务，不重复创建，不静默改绑其他 QQ。
- 自动维护只接受当事人明确陈述的受限长期状态；self 必须由可信主人确认，owner 仅接受其本人发言。身份、权限与手动核心资料仍受主人权限保护，群友不能用聊天命令覆盖。

```text
special/self                        DSH 自身身份
special/owner                       主人身份、来源与主题引用
direct/QQ甲                         私聊首次出现时的临时归档位置
groups/群A/people/QQ甲                QQ甲唯一档案与成员关系
groups/群B/people/QQ甲 -> 群A/QQ甲     引用同一档案
groups/任意群/people/主人QQ -> owner  引用主人档案
```

以上是事务性 JSON 内的逻辑地址。首次群指插件首次接收到可信消息时的群，不扫描旧历史推断更早位置。

## 对话工具

| 工具 | 用途 |
|---|---|
| `identity_read` | 读取当前可见的 self、owner 或 QQ 档案 |
| `identity_bind_owner` | 本机主人明确要求时绑定 QQ，合并已有身份 |
| `identity_update_profile` | 更新已确认资料；self/owner 核心受主人权限保护 |
| `memory_recall` | 检索索引，实际读取授权 Skill 和 MCP 资源 |
| `memory_end_topic` | 无参数，标记当前完整回复结束后关闭主题；明确换话题时会先关闭之前的主题 |
| `memory_set_directory` | 本机主人明确要求时在线切换索引目录 |
| `memory_rate` | 本机主人改写一条事件记忆的 β，或删除改写恢复自动推导 |
| `memory_inspect_record` | 纠错前读取准确事件或人物、版本哈希及可见印象 |
| `memory_correct_event` | 更正或撤回事件，同步撤下错误投影和依赖印象 |
| `memory_correct_profile` | 版本核对后修订已确认人物资料或清除错误字段 |
| `memory_retract_impression` | 撤回一条推测印象，阻止旧证据重复建立 |
| `memory_revision_history` | 本机主人查看修订元数据及待重试状态 |

可编辑字段为 `displayName`、`description`、`persona`、`traits`、`preferences`、`notes`，以及 `speakingStyle`（说话风格）、`characterStyle`（人物风格）、`occupation`（职业）、`longTermStatus`（长期状态）。这些核心字段不设置十天有效期，但“长期稳定”不等于永远不能纠正。未知资料留空；owner 的私人资料不会因其 QQ 出现在群里而公开。子任务不继承主会话人物权限；混合不相容聊天来源时停止召回和摘要，避免串群串人。

## 索引目录设置

默认身份目录为 `<DSH_HOME>/identity-vault`；没有 `DSH_HOME` 时为 `~/.dsh/identity-vault`。索引默认放在其中的 `memory-index` 子目录，也可配置其他绝对目录。包本身不固定盘符。

在线修改：在本机主人对话中明确指定新的绝对目录，由 `memory_set_directory` 操作。离线修改：先退出 DSH，再执行：

```text
node bin/cli.mjs memory-directory
node bin/cli.mjs memory-directory "<新的绝对索引目录>"
node bin/cli.mjs memory-directory "<新的绝对索引目录>" "<自定义身份目录>"
node bin/cli.mjs memory-directory "" "<自定义身份目录>"
```

不传新目录时只显示配置。切换先复制并验证索引，再原子更新身份目录中的 `memory-settings.json`；原索引目录保留。身份与事件正文不会随索引目录搬迁。目标目录有冲突时明确失败，不静默覆盖。

## 安装与升级

使用现有 DSH profile 安装，保持同一个 `dsh-identity-vault` bundle。手动操作前退出 DSH，用可用的 pnpm（可使用 DSH 自带运行时）安装本地目录或打包文件：

```text
pnpm --dir "<DSH profile目录>" add "<本包目录或tgz文件>" "billion-context" "github:Yuuyuko-uu/dsh-fish-memory" --ignore-scripts
```

本包声明必须存在的 peer dependencies：`dsh-fish-memory` 和 `billion-context`，版本范围为 `*`，实际兼容性由启动能力检查决定。上述命令适用于首次安装；已经安装后端时可仅安装本包，保留现有上游版本。两个后端由依赖管理器安装，不复制到本插件源码包内。

在 profile 的 `package.json` 中，将 `dsh-identity-vault` 加入 `dsh.profile.bundles` 数组，并从该数组移除 `dsh-fish-memory` 与 `billion-context` 的独立 bundle。保留这两个包的依赖及其他已有 bundle，避免原生后端和主插件重复挂载。更换上游版本后完整重启 DSH，由适配器重新验证实际能力。

包内 `cordis.patch.yml` 注册主插件及受管压缩门控，保留四个 preset 的门控依赖和 DeepSeek 重试兼容设置，不独立插入 `bili-native`。是否关闭原生压缩由门控在启动时动态决定；受管后端初始化失败或超时时，保留 preset 原有压缩设置，包括用户既有的 `auto` 开关。Cordis patch 对 `config` 和 `inject` 的替换不是深合并；升级 DSH、使用自定义 preset 或覆盖同名行后，需核验合成配置。升级沿用身份目录，不创建第二个记忆插件。桌面默认 profile 通常为 `~/.dsh/profiles/desktop`，以本机配置为准。

本版使用 DSH 0.2.1-rc.3 的原生 MCP 资源和 Skill provider 契约。缺少这些服务时明确报错，不把同名普通函数当作读取成功。

每个会话通过独立的依赖注入上下文注册记忆工具、MCP 资源、Skill 与提示词，并使用同一上下文读取记忆；不能直接借用全局插件的依赖声明访问 `agent.ctx` 的服务。0.9.1 修复了此前会导致新建对话失败、选择工作区后自动退回的会话挂载问题，并通过 Cordis 正式的 effect 生命周期在会话或插件卸载时清理资源和后台任务。

## QQ 适配

内置 `dsh-qq-bridge` 来源适配器 v2，在可信边界提供数字 QQ、群号、用户正文范围与回复标记策略。兼容判断依据收发结构与实际能力，版本号仅用于诊断。只概括实际聊天正文，不把昵称、桥接提示、图片路径、思考块或工具日志当作发言；图片只记录“发送图片、内容未分析”。

适配器还核验 QQ 桥按会话缓存最后一条助手正文、仅在同一轮完成后分发并清空缓存的链路；事件只总结这一条，并按桥策略去除 `[QQ]` 标签或仅取公开块。若上游改为累计多条回复、改变正文提取或跨会话/轮次分发，会明确拒绝适配。来源标记为“已生成、未确认送达”。生成回复不等于 QQ 成功收到，本版没有出站回执同步。

```text
node bin/cli.mjs adapter-prepare "<QQ桥包>/lib/host.js"
node bin/cli.mjs adapter-install "<QQ桥包>/lib/host.js"
node bin/cli.mjs adapter-check "<QQ桥包>/lib/host.js"
node bin/cli.mjs adapter-remove "<QQ桥包>/lib/host.js"
```

安装前核对必要收发能力、源码、备份和清单；可升级经校验的 v1 适配并保留原件。安装或恢复后重载宿主。运行时只校验，不擅自改写其他插件，也不改变登录、群过滤、回复门槛或发送设置。桥升级后需重新验证；全新上游包需重新运行适配安装。若升级覆盖源码却留下旧备份/清单，会报告 `bridge-changed` 并拒绝覆盖；先保留旧备份，再对干净重装的上游包适配。不兼容或缺少原话范围时不从正文猜身份。上游连续消息合并只给首个消息 ID 时，明确标为 `upstreamFirstMessageId`。

`dsh-im` 官方 QQ 通道的 OpenID 不等于数字 QQ 号，本版不自动合并或绑定该通道身份；其他外部渠道需要独立可信适配。

## 旧数据与维护

启动及旧摘要任务完成后，把来源可验证、符合新格式且尚未过期的旧摘要逐条迁为事件 Skill。一个旧单人摘要对应一个历史事件，不编造过去的多人主题。迁移 ID 不依赖当前 canonical 地址，主人绑定或首次群迁移后重跑仍幂等。旧数据按来源消息最新时间计时；达到十天的旧摘要会过期清理，不因升级或重新生成摘要而重新获得十天寿命。

任意手工来源 ID、无法确认作者的引用、超出新格式的长文本等明确跳过。只有未迁移且尚未过期的条目继续使用旧摘要回退；已迁移后被归档或遗忘的内容不会从回退重新进入上下文。过期条目单独计数，不进入兼容回退。旧正文不补造缺失的事实/评价分类。迁移不调用模型、不虚构来源、不截断晚出现的更正。

| 文件或目录 | 内容 |
|---|---|
| `identity-state.json` | 身份、MCP 重要投影、当前长期状态、跨事件推测印象及证据元数据、旧摘要、来源和主题引用、旧摘要任务 |
| `identity-state.previous.json` | 上一成功版本 |
| `memory-settings.json` | 索引目录配置 |
| `conversations.json` | 待总结的连续多轮会话元数据，只存来源引用 |
| `topics/manifest.json` | 活跃事件、到期与重复关联元数据、任务；已遗忘事件的最小墓碑 |
| `topics/events/<ID>/SKILL.md` | 主题摘要正文，全部按原始来源时间保留 240 小时 |
| `backend-candidates.json` | 有界临时候选收件箱、证据元数据和二层分类待提交决策，不是记忆索引 |
| `impression-worker/` | 长期印象处理指纹、重试状态和已验证待写概括；不存普通事件正文 |
| `revisions/event-queue.json` | 待完成事件修订与成功哈希回执；排队摘要不超出原 Skill 期限 |
| `managed-billion/` | 受管代理的专属配置、工作区及压缩结果去重回执；不纳入 Skill 的十天清理 |
| `runtime-status.json` | 版本、适配、任务、迁移、维护和后端计数、子进程 PID/端口、待重试状态及错误代码，无聊天正文 |
| `<索引目录>/memory-index.json` | 七字段索引，无摘要正文或人格资料 |

命令行状态保留旧身份库字段，补充索引配置、索引状态、过期任务、事件清理及维护计数，不输出档案、长期状态内容或聊天正文：

```text
node bin/cli.mjs status
node bin/cli.mjs status "<自定义身份目录>"
node bin/cli.mjs init "<自定义身份目录>"
```

数据使用原子提交和独占写锁；坏库不自动清空，遗留锁不盲目抢占。旧 v1/v2 身份文件兼容读取。禁用或卸载不删除数据。任务恢复依赖原 DSH 会话仍存在；原会话删除、来源校验失败或模型不可用会保留失败状态。插件停用取消自己的后台工作。权限仅约束本插件接口，不隔离同一系统账户对文件的任意访问。

当前已实现身份、按人物调度、多轮主题 Skill、原生 MCP 资源、有界召回、相同完整摘要的逻辑归并、明确长期状态维护、重要 MCP 投影、跨事件推测印象、全部 Skill 十天淡忘、修订撤回与审计，以及两个受管后端的统一候选入口。没有语义 embedding、语义相似事件自动归并或图形化修订历史面板；修订通过对话工具完成。长期与临时语义分类、跨事件模式判断和纠错对象选择依赖模型理解，宿主另行校验证据作者、独立事件数、日期跨度、范围、字段、时间与版本，真实模型仍可能误解含糊表达。
